# FireTV agent access

Use the authorized ADB connection and `canvas-tvctl` to control fungOS Canvas on
the FireTV Omni. The control credential is generated by the app and rotates when
its process restarts. Retrieve the current credential through ADB; never copy a
token into repository files, chat, or shared notes.

## Target and control client

- ADB serial: `192.168.2.97:5555`.
- Package: `dev.fpl.canvas.tv`.
- Activity: `dev.fpl.canvas.tv/dev.fpl.canvas.TvActivity`.
- Control listener: device loopback `127.0.0.1:27841`, not a public LAN API.
- Neo client: `/Users/ajmwagar/.local/bin/canvas-tvctl`.
- Client source: `src/bin/canvas-tvctl.rs` in this crate.

```sh
adb devices -l
printf 'inspect\n' | canvas-tvctl 192.168.2.97:5555
printf 'workspace read television\n' | canvas-tvctl 192.168.2.97:5555
printf 'workspace switch television\n' | canvas-tvctl 192.168.2.97:5555
```

Always pass the explicit serial: a Quest is also attached to Neo. The client
reads the app-private token with `adb shell run-as dev.fpl.canvas.tv`, creates a
temporary ADB TCP forward, authenticates the request, and removes the forward.
It handles revision lookup for its text workspace commands. JSON mutations
require the current target revision; catalog discovery and execution must use
the same TV endpoint.

## Credential location and failures

The current control token is `files/control-token` inside the app's private
directory, `/data/user/0/dev.fpl.canvas.tv/`. A custom client must obtain it
through the authorized ADB `run-as` path, keep it in memory or an owner-private
temporary file, and send the token as the first protocol line followed by one
JSON request line. Prefer `canvas-tvctl` instead of implementing this again.

If `run-as` fails, verify the explicit package and that the authorized development
build is installed. Do not reinstall, clear app data, or rotate credentials just
to obtain a token. If the token is absent, inspect the activity and start the app
only when doing so will not interrupt someone else's session. After an app
restart, fetch a fresh token rather than retrying a saved one.

## Development signing key

The local development keystore is
`/Users/ajmwagar/.local/share/canvas-android/debug.keystore`; the packaging runbook
uses alias `canvas-tv-debug`. This is distinct from the control token and AirPlay
pairing. Keep the keystore private and reuse it for compatible updates; do not
create a replacement key or uninstall the app to bypass signing failures.
Packaging instructions are in `README.md` in this crate.

## Playback test coordination

AirPlay has its own `airplay` workspace and `cast-airplay-video` surface,
pointing to `http://192.168.2.67:8099/live.m3u8`. Select it with:

```sh
printf 'workspace switch airplay\n' | canvas-tvctl 192.168.2.97:5555
```

The retained document template is `config/deploy/firetv/airplay.json` in the
repository. Add it to the current catalog with a revision-bound install that
preserves all existing projects and documents; it is not a replacement catalog.
Do not put AirPlay in the Television workspace: tuner controls previously
replaced its active stream with KOMO, invalidating playback measurements.
Verify the selected document and URL before counting frames.

Do not install an APK, force-stop the app, switch workspaces, or restart a stream
backend during another agent's playback measurement. Those actions interrupt
video and invalidate a stability result. Inspect first and coordinate changes.
