# Blitz on wasm32-wasip2

A proof that Blitz can render HTML/CSS inside a Spore component and hand the
host pixels, with no browser and no JavaScript.

```sh
cargo build --target wasm32-wasip2 --release
wasmtime run --dir . target/wasm32-wasip2/release/blitz-wasm-probe.wasm
wasmtime run --dir . target/wasm32-wasip2/release/vitals.wasm
```

`vitals.rgba` is 1200x900 RGBA8 from `fixtures/vitals.html`, generated by the
Soil Vitals example. Convert it with Pillow or any RGBA reader.

## Measured here

- `blitz-html` + `blitz-dom` (`default-features = false`, `svg`) +
  `blitz-paint` + `anyrender_vello_cpu` compile to `wasm32-wasip2`.
- minimal 400x200 render: 320,000 bytes RGBA.
- Vitals 1200x900: 4,320,000 bytes RGBA, ~2.8s including wasmtime startup.
- release wasm: 15 MB per binary before other assets.
- system fonts do not exist in wasm. Embed a font with
  `build_single_font_ctx`, and set `font-family` explicitly, including on SVG
  `<text>`; otherwise text is invisible.

## Why this matters

`soil:surface@1.1.0` already carries `Present::Rgba { width, height, pixels }`.
So the guest can run Blitz, render its own HTML/CSS, and present the RGBA buffer
through the existing surface contract. The host remains a dumb presenter; there
is no host Blitz, no `soil:ui` document contract, and no scene graph in this
path.

`fixtures/vitals.html` is a generated artifact used to measure the second case.
The font is IBM Plex Sans under the SIL Open Font License; see
`assets/IBMPlexSans-license.txt`.
